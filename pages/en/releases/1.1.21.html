relay-knowledge 1.1.21 release notes

This patch fixes permanent index-task recovery, keeps large impact queries within SQLite and memory budgets, and narrows source fallback to the requested path scope.

Release date: October 12, 2026.

Release downloads crates.io Checksums

Install and verify

cargo install relay-knowledge --version 1.1.21 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

Download the archive for your platform and verify its checksum and GitHub attestation before installation. The separate CLI skill archive includes the same version's Linux x64 and Windows x64 binaries.

What changed

  • Immutable delta files that exceed their frozen byte or row budget return resource_budget_exceeded and become dead letters on that attempt. Transient capacity pressure retains bounded retries; failed targets do not replace published facts.
  • Canonical incremental-clone checkpoints retain their durable origin after terminal task audit pruning, so later valid targets are not blocked as unfinished direct writes. Genuine direct checkpoints still require resume or adoption.
  • Impact evidence splits path and symbol seeds into at most 500 bind values plus snapshot scope per batch. Every batch participates in a deduplicating top-k merge with bounded retained rows, preserving filters and late-batch ranking.
  • Source fallback intersects registered and requested path-prefix groups before discovering candidates or reading source. Complete path segments, disjoint and separator-only scopes, explicit files, and lexical and declaration results share the same narrowing.
  • Regression coverage includes oversized-owner recovery to a repaired commit, successor admission after terminal failure, large impact seed sets and retained evidence, and path-scope intersections.

Upgrade and rollback

Back up runtime databases and all shards, private feedback journals, and repository-owned maps and research artifacts. Stop resident services and drain or cancel active work before replacing binaries or restoring a consistent backup.

This patch introduces no database or map schema migration and no new runtime directory. Preserve task records, attempt leases, checkpoints and retry deadlines. Existing queued or retrying tasks receive the new permanent-failure classification on their next fenced attempt.

For resource_budget_exceeded, repair or split the source artifact in a new commit and submit that immutable head once. repo index --reset only requeues unfinished tasks with their original inputs and budgets; it does not revive dead letters. Do not delete task history or reset leases.

Confirm last_indexed_commit equals the requested head and stale is false; inspect content_integrity for parser or source-I/O gaps. For large impact queries, retain the pinned base/head pair and retry with the updated runtime.

For rollback, stop all writers and restore a matching backup when needed. Version 1.1.20 can reproduce the fixed failure, query and filtering behavior; it does not automatically revive terminal tasks. Repository Map v4 still requires a 1.1.17 or newer reader; existing Windows account-SID and ACL requirements remain in effect.

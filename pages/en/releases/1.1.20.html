relay-knowledge 1.1.20 release notes

This patch fixes delta admission that could prevent code-index tasks from advancing and documents bounded queue recovery.

Release date: October 10, 2026.

Release downloads crates.io Checksums

Install and verify

cargo install relay-knowledge --version 1.1.20 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

Download the archive for your platform and verify its checksum and GitHub attestation before installation. The separate CLI skill archive includes the same version's Linux x64 and Windows x64 binaries.

What changed

  • Previously admissible delta partitions retain their batch membership and replay cursor. Plans rejected for capacity can account for staged facts separately from deferred edges without changing an already committed batch.
  • Reference and import facts remain staged; call rows and edge search projections are built by separately budgeted finalization pages before the scope becomes queryable. Search writes and edge finalization remain required.
  • Symbol and chunk admission measure actual UTF-8 search text and metadata bytes, with explicit row/control overhead. Capacity errors expose fact/control bytes, rows and configured limits.
  • The CLI skill explains how to inspect full queues, follow managed task progress and run one bounded local worker attempt when the managed service is disabled. Recovery preserves leases, backoff, checkpoints and queue capacity.
  • Regression tests cover dense references, large UTF-8 search content, replay-stable partitions, truly oversized owners and end-to-end delta cloning.

Upgrade and rollback

Back up runtime databases and all shards, private feedback journals, and repository-owned maps and research artifacts. Stop resident services and drain or cancel active work before replacing binaries or restoring a consistent backup.

This patch introduces no database or map schema migration and no new runtime directory. Preserve task records, attempt leases, checkpoints and retry deadlines. Resume eligible work through the managed service; never delete task rows or reset leases to clear a queue.

On a local service host with the managed service disabled, inspect repo status and service doctor, run one index-worker attempt for the active task, then inspect progress again. Repeated capacity or invariant failures and dead-letter tasks need diagnosis.

After capacity becomes available, submit the latest immutable head once. Confirm last_indexed_commit equals that head and stale is false; also inspect content_integrity for parser or source-I/O gaps.

For rollback, stop all writers and restore a matching backup when needed. Version 1.1.19 can reproduce the original admission failure. Repository Map v4 still requires a 1.1.17 or newer reader; existing Windows account-SID and ACL requirements remain in effect.

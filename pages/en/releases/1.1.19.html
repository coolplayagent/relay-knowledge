relay-knowledge 1.1.19 release notes

Atomic map changes, scoped research evidence and durable software feedback now share the CLI and Web application services.

Release date: October 9, 2026.

Release downloads crates.io Checksums

Install and verify

cargo install relay-knowledge --version 1.1.19 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

Download the archive for your platform and verify its checksum and GitHub attestation before installation. The separate CLI skill archive includes the same version's Linux x64 and Windows x64 binaries.

What changed

  • map plan and map apply validate up to 100 ordered source changes and publish one map version. Version/digest preconditions, bounded replay receipts and existing writer locks prevent partial batch publication.
  • sources audit verifies explicitly declared local captures and extraction bindings. Authored evidence bundles support validation, scoped import/export, graph views and impact proposals while preserving source hashes and proposed fact status.
  • research status reports archive, authored-graph and GraphRAG readiness separately. Fresh indexes, intact bytes and self-reported review claims do not establish that a research question is answered.
  • Nine feedback commands preserve private local reports, preview public payloads, deduplicate publication and reconcile uncertain sends. GitHub publication requires explicit policy; fix verification requires separately authorized runner evidence.
  • Feedback validation enforces UTF-8 byte bounds and final report size after correlation IDs are filled. Web status rejects invalid ID types, and GitHub rate-limit deadlines survive restart without early remote retries.
  • Invalid stored ontology identities receive explicit handling. The browser-test dependency lock updates urllib3 from 2.7.0 to 2.8.0.

Upgrade and rollback

Back up repository-owned maps, captured sources and evidence bundles, the runtime database and all shards, and the private runtime feedback directory. Stop resident services and drain or cancel active work before replacing binaries or restoring a consistent backup.

Batch receipts reuse Repository Map v4 and its existing 16-entry history; no map schema bump is required. Keep long-term transaction evidence in Git or backups. Research imports reuse existing graph storage and indexes, and imported facts remain proposed until reviewed through the existing lifecycle.

Feedback adds a separate bounded journal under the configured runtime data directory. Older binaries cannot reconcile pending feedback publications. Preserve nonce identities, send intent and retry deadlines when upgrading or rolling back; never discard an uncertain publication to force a second create. Publication remains disabled until explicitly configured.

Existing Windows account-SID path and ACL requirements remain unchanged. Repository Map v4 needs a 1.1.17 or newer reader. This release introduces no automatic downloads of research sources, new background service or automatic software upgrade.

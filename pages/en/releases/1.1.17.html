relay-knowledge 1.1.17 release notes

Version 1.1.17 introduces Repository Map v4 with bounded recent history, reduces map storage writes, and strengthens migration and recovery. It also improves durable worktree indexing and consolidates the software ontology schema.

Release date: September 7, 2026.

Release downloads crates.io Checksums

Install and verify

cargo install relay-knowledge --version 1.1.17 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json

Upgrade every writer and reader that shares a repository before migrating its visible Repository Map v4 contract. Version 1.1.17 is the minimum v4 reader. Back up or commit repository-owned map files before a migration, and use the documented service lifecycle dry-run before replacing a resident service binary. There is no data-level map rollback command: restore the pre-migration map snapshot from Git or backup before running an older binary. Back up runtime databases and all shards for an exact rollback of storage migrations.

Repository Map v4

CodeSpec and Knowledge maps keep their visible codespec/ and knowledge/ roots. Each root retains the latest 16 history entries; omitted_through records the discarded-history checkpoint. Requests for older history fail explicitly. Long-term audit and recovery use Git or repository backups.

  • Migration validates the complete authorized legacy history chain before publishing v4 roots and the legacy redirect.
  • Cleanup waits for a 60-second reader grace period and removes at most 1,024 recognized files per pass.
  • Symlinks, unknown entries, unsafe paths, and integrity failures stop cleanup without deleting unrecognized data.
  • Run map init again to continue pending cleanup; map validate remains read-only.

Less map storage churn

  • Unchanged source updates no longer consume map/source versions or write new topic shards.
  • Topic-shard cleanup preserves current and fallback reader roots and uses bounded, resumable maintenance.
  • Recovery and migration validate ownership and legacy state under repository writer locks.

Indexing and ontology

  • Durable worktree indexing strengthens recovery and publication checks while retaining leases and checkpoints.
  • Read-only catalog startup avoids taking a catalog writer lock.
  • Software ontology projections share a core schema for vocabulary, properties, and validation.
  • Layered commit quality gates and high-dimensional indexing validation strengthen regression coverage.

Release packages

The release contains six platform archives, checksums.txt, artifact attestations, and the versioned CLI skill archive. Linux GNU binaries are built and started on a glibc 2.28 baseline before publication.

  • macOS Intel and Apple Silicon
  • Windows x64 and ARM64

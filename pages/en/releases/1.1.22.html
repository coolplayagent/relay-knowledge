relay-knowledge 1.1.22 release notes

This patch accepts Windows-style proxy addresses, keeps local diagnostics available when a proxy is invalid, and gives health checks cancellable deadlines with actionable maintenance advice.

Release date: October 16, 2026.

Release downloads crates.io Checksums

Install and verify

cargo install relay-knowledge --version 1.1.22 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

Download the archive for your platform and verify its checksum and GitHub attestation before installation. The separate CLI skill archive includes the same version's Linux x64 and Windows x64 binaries.

What changed

  • HTTP(S) proxies accept host:port, IPv4 and bracketed IPv6 authorities. Invalid, empty or non-Unicode environment proxy values fall back to a direct connection with a credential-free runtime.http_proxy_warning; TLS verification and NO_PROXY policy remain in effect.
  • RELAY_KNOWLEDGE_HEALTH_STORAGE_BUDGET_MS defaults to 500 ms and accepts 1–30000 ms. The effective budget reserves time before the shortest issued HTTP request deadline and covers storage snapshots, model-profile loading and response assembly.
  • Health SQLite reads use nonblocking admission and observe request cancellation, including partition catalog and totals reads. A timeout retains explicit storage_busy, stale and unhealthy state without increasing SQLite busy timeouts.
  • All service clones share at most one profile-read worker with no waiting queue. Its permit lasts until the filesystem read finishes, even after request cancellation. Repeated probes return cached or uninspected summaries with pending/stale diagnostics; fallback responses do not reload profile files.
  • CLI and Web Runtime diagnostics expose proxy warnings, effective budgets, degradation reasons and maintenance advice. Partitioned maintenance timestamps preserve the oldest record; missing or unreadable history remains unknown.
  • Observed large WAL files, overdue or failed maintenance, and missing history receive inspection advice. Timeout alone does not establish WAL pressure. Health probes do not perform checkpoints or delete WAL files; setup doctor proxy warnings do not block configuration readiness.

Upgrade and rollback

Back up runtime databases and all shards, private feedback journals, and repository-owned maps and research artifacts. Stop resident services and drain or cancel active work before replacing binaries or restoring a consistent backup.

This patch adds no database or map schema migration and no runtime directory. Preserve runtime configuration, databases, shards, task leases, checkpoints and retry deadlines. Existing Repository Map v4 and Windows SID/ACL requirements remain unchanged.

For slow stores, configure the managed service environment with a health budget such as 5000 ms, then restart the service. runtime.health_storage_budget_ms reports the effective value, which remains below the shortest issued HTTP timeout. Raising that ceiling also requires a restart; initial database opening and schema initialization remain startup work.

Inspect runtime.http_proxy_warning separately from storage_busy or storage_cold. Deployments that require a proxy must correct any direct-fallback warning. Run service doctor and review managed-service maintenance logs before scheduling a checkpoint; retain WAL files and runtime state.

Before rollback, stop all writers, retain or restore a consistent backup, and set complete HTTP(S) proxy URLs. Version 1.1.21 lacks the configurable health budget and may reproduce the fixed proxy or timeout behavior. Uninstalling the binary must preserve runtime data and repository-owned artifacts unless deletion is explicitly requested.

Check the effective budget

The following is a POSIX shell example for one CLI invocation. Configure the equivalent environment in your platform service manager for background operation.

RELAY_KNOWLEDGE_HEALTH_STORAGE_BUDGET_MS=5000 relay-knowledge health --format json
relay-knowledge setup doctor --format json
relay-knowledge service doctor --format json

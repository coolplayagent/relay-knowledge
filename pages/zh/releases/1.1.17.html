relay-knowledge 1.1.17 发布说明

1.1.17 引入仅保留最近历史的 Repository Map v4，减少地图存储写入并加强迁移与恢复。 本版同时改进耐久 worktree 索引，收敛软件本体的核心 schema。

发布日期：2026 年 9 月 7 日。

发布与下载 crates.io Checksums

安装与验证

cargo install relay-knowledge --version 1.1.17 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json

迁移可见的 Repository Map v4 合同前，应先升级所有共享该仓库的 writer 与 reader。 迁移前备份或提交仓库拥有的 map 文件；替换常驻服务二进制前，先运行文档规定的 service lifecycle dry-run。1.1.17 是最低 v4 reader 版本。 地图不提供数据级 rollback 命令：启动旧二进制前，先从 Git 或备份恢复迁移前的 map snapshot。 存储迁移的精确回滚还需要备份 runtime database 和全部 shard。

Repository Map v4

CodeSpec 与 Knowledge Map 继续使用可见的 codespec/ 与 knowledge/ 根目录。每个根只保留最近 16 条历史， omitted_through 记录被丢弃历史的 checkpoint；请求更早历史会明确失败。 长期审计与恢复依赖 Git 或仓库备份。

  • 迁移先校验完整且经过授权的 legacy history chain，再发布 v4 根和 legacy redirect。
  • 清理等待 60 秒 reader grace，每轮最多删除 1,024 个已识别文件。
  • 符号链接、未知条目、不安全路径或完整性失败会停止清理，不删除未识别数据。
  • 再次运行 map init 可续跑待完成清理；map validate 始终只读。

减少地图存储写入

  • 相同内容的 source update 不再消耗 map/source version，也不写入新 topic shard。
  • Topic-shard 清理保留 current 与 fallback reader root，并通过有界、可续跑的维护执行。
  • 恢复与迁移在 repository writer lock 内校验 ownership 和 legacy 状态。

索引与本体

  • 耐久 worktree 索引加强恢复与发布校验，继续保留 lease 和 checkpoint。
  • 只读 catalog 启动避免获取 catalog writer lock。
  • 软件本体投影共享核心 schema，统一词汇、属性和验证规则。
  • 分层 commit 质量门禁与高维索引验证加强回归覆盖。

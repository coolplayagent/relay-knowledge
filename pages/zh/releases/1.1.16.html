relay-knowledge 1.1.16 发布说明

1.1.16 将仓库拥有的 CodeSpec 与 Knowledge Map 收敛为强类型、agent 可发现的合同， 并加强耐久代码索引与软件投影的生命周期边界。这一版还新增 Angular 和 Vue 框架图抽取，更新了跨平台发布基线。

发布日期：2026 年 8 月 30 日。

发布与下载 crates.io Checksums

安装与验证

cargo install relay-knowledge --version 1.1.16 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json

迁移可见的 Repository Map v3 合同前，应先升级所有共享该仓库的 writer 与 reader。 迁移前备份或提交仓库拥有的 map 文件；替换常驻服务二进制前，先运行文档规定的 service lifecycle dry-run。

强类型 CodeSpec 与 Knowledge Map

Repository Map v3 使用可见的 codespec/ 与 knowledge/ 根目录。 CLI 通过统一的校验、查看、路由和迁移入口暴露两种 map，agent 不必再从文件布局猜测仓库合同。

  • map validate --type all 同时校验两个受治理根目录，只报告诊断，不重写内容。
  • map show 暴露强类型目录范围、关键文件、加载策略、更新策略和跨 map 关系。
  • map route 解析仓库业务词汇表等 authored source。
  • CLI skill 包含 Knowledge Map、CodeSpec Map 与 Business Glossary 的 Draft 2020-12 schema。
  • Foundational 自迭代用例保护 help 发现、双 map 校验、目录过滤与业务路由。

框架图与软件全域覆盖

仓库图现在抽取 Angular 和 Vue 框架证据，并让软件投影与代码事实绑定到同一已提交 source scope。 授权范围外缺失的外部包继续表示为 unresolved edge metadata，不会被误报为仓库损坏。

  • 框架查询按证据暴露组件、路由、依赖和相关图边。
  • 软件投影通过耐久、lease-aware 工作发布，不绕过索引 ownership。
  • Repository status 持续暴露 freshness、active task、checkpoint 和 publication state。
relay-knowledge repo framework <alias> \
  --framework angular --kind component \
  --ref <commit> --freshness wait-until-fresh --format json

relay-knowledge repo software <alias> \
  --kind relationships --ref <commit> \
  --freshness wait-until-fresh --format json

耐久索引与架构边界

  • 索引编排拆分为明确的 start、session、worker、recovery、snapshot、projection 和 publication 职责。
  • 仓库工作保留 durable task lease、有界重试、checkpoint、single-writer ownership 与 publication fence。
  • 更强的架构门禁约束 clock、identity、runtime、storage、network 和 service lifecycle ownership。
  • 大型软件投影使用 lease-friendly 的有界工作，避免 maintenance 阻塞查询热路径。

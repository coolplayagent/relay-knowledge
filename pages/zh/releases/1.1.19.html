relay-knowledge 1.1.19 发布说明

本版增加原子地图批处理、按范围绑定的研究证据工作流和持久软件反馈，CLI 与 Web 共享应用服务。

发布日期：2026 年 10 月 9 日。

发布与下载 crates.io Checksums

安装与验证

cargo install relay-knowledge --version 1.1.19 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

下载适合平台的压缩包，安装前校验 checksum 和 GitHub attestation。独立 CLI Skill 压缩包包含同版本的 Linux x64 与 Windows x64 二进制。

本版变化

  • map plan 与 map apply 校验最多 100 项有序来源变更，并只发布一个地图版本。版本与摘要前置条件、有界重放回执及既有 writer lock 防止只提交部分批次。
  • sources audit 核验明确声明的本地采集材料与提取绑定；研究证据包支持校验、按范围导入导出、图视图和影响提案，保留来源哈希及 proposed 事实状态。
  • research status 分别报告归档、作者图谱和 GraphRAG 就绪状态。索引新鲜、字节完整或自报审阅记录，都不能单独证明研究问题已得到回答。
  • 九个反馈命令保存私有本地报告、预览公开内容、去重发布并核对不确定发送。GitHub 发布需要明确策略，验证修复需要独立授权的 runner 证据。
  • 反馈校验覆盖 UTF-8 字节边界及补齐关联 ID 后的报告总大小；Web 状态接口拒绝错误 ID 类型，GitHub 限流期限在重启后仍有效，期限前不发起远端重试。
  • 明确处理存储中的无效 ontology 身份；浏览器测试依赖 urllib3 从 2.7.0 更新为 2.8.0。

升级与回滚

备份仓库拥有的地图、采集原文与证据包、运行时数据库和全部分片，以及私有运行时 feedback 目录。替换二进制或恢复一致备份前，停止常驻服务并等待或取消活动任务。

批处理回执复用 Repository Map v4 及现有 16 项历史窗口，不提升 map schema。长期事务证据保存在 Git 或备份中。研究导入复用既有图存储与索引，导入事实保持 proposed，直到通过现有生命周期审阅。

反馈在配置的运行时数据目录下使用独立有界 journal。旧二进制无法核对待定反馈发布；升级和回滚必须保留 nonce 身份、发送意图及重试期限，不能删除不确定发布来强制再次创建 issue。发布默认关闭，必须明确配置授权。

Windows 账户 SID 路径与 ACL 要求保持不变。Repository Map v4 需要 1.1.17 或更新 reader。本版不增加研究来源自动下载、新后台服务或自动软件升级。

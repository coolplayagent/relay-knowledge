relay-knowledge 1.1.22 发布说明

本补丁支持 Windows 风格的代理地址，在代理无效时保留本地诊断，并为健康检查提供可取消的截止时间及维护建议。

发布日期：2026 年 10 月 16 日。

发布与下载 crates.io Checksums

安装与验证

cargo install relay-knowledge --version 1.1.22 --locked
relay-knowledge version --format json
relay-knowledge map validate --type all --format json
relay-knowledge service doctor --format json

下载适合平台的压缩包，安装前校验 checksum 和 GitHub attestation。独立 CLI Skill 压缩包包含同版本的 Linux x64 与 Windows x64 二进制。

本版变化

  • HTTP(S) 代理支持 host:port、IPv4 和带方括号的 IPv6 地址。非法、空或非 Unicode 环境代理回退直连，并通过 runtime.http_proxy_warning 提供不含凭据的警告；TLS 验证与 NO_PROXY 策略继续生效。
  • RELAY_KNOWLEDGE_HEALTH_STORAGE_BUDGET_MS 默认 500ms，范围为 1–30000ms。生效预算在历次已发布 HTTP request timeout 的最小值之前预留时间，同时覆盖存储快照、model profile 读取与响应组装。
  • 健康 SQLite 读取采用非阻塞准入并响应请求取消，包含分片目录与 totals 读取。超时保留显式 storage_busy、stale 和不健康状态，不增加 SQLite busy timeout。
  • 所有服务克隆共享最多一个 profile 读取 worker，无等待队列；即使请求取消，准入令牌也保留到实际文件读取结束。重复探测返回带 pending/stale 说明的缓存或未检查摘要，降级响应不会重新读取 profile 文件。
  • CLI 与 Web Runtime 诊断展示代理警告、生效预算、降级原因及维护建议。分片维护时间取最旧记录；任何记录缺失或不可读时保留未知状态。
  • 对已观察到的大 WAL、过期或失败维护、缺失维护历史给出排查建议。超时本身不证明 WAL 压力；健康检查不执行 checkpoint，也不删除 WAL。setup doctor 的代理警告不阻断配置 readiness。

升级与回滚

备份运行时数据库及全部分片、私有反馈 journal、仓库拥有的地图和研究材料。替换二进制或恢复一致备份前，停止常驻服务并等待或取消活动任务。

本补丁不增加数据库或地图 schema migration，也不增加运行时目录。保留运行时配置、数据库、全部分片、任务 lease、checkpoint 和重试期限。既有 Repository Map v4 与 Windows SID/ACL 要求继续有效。

慢存储可先在托管服务环境中设置 5000ms 健康预算，然后重启服务。runtime.health_storage_budget_ms 返回生效值，仍受历次已发布 HTTP timeout 最小值限制；提高该上限也需要重启。初次数据库打开和 schema 初始化仍属于启动流程。

分别检查 runtime.http_proxy_warning 与 storage_busy/storage_cold。要求强制代理的部署必须修正直连降级警告。安排 checkpoint 前先运行 service doctor 并检查托管服务维护日志；保留 WAL 文件与运行时状态。

回滚前停止全部 writer，保留或恢复一致备份，并设置完整 HTTP(S) 代理 URL。1.1.21 没有可配置健康预算，可能重现已修复的代理或超时行为。卸载二进制时应保留运行时数据及仓库拥有的材料，除非明确请求删除。

检查生效预算

以下为单次 CLI 调用的 POSIX shell 示例。后台运行时应在平台服务管理器中配置对应环境变量。

RELAY_KNOWLEDGE_HEALTH_STORAGE_BUDGET_MS=5000 relay-knowledge health --format json
relay-knowledge setup doctor --format json
relay-knowledge service doctor --format json
